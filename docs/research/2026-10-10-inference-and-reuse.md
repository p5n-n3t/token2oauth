# Inference providers and reuse options

**Verified:** 2026-10-10 · **Scope:** official documentation and repository pages only. No inference/API calls, sign-ins, installs, or credential handling were performed. The current `package.json` describes a TypeScript/Express/Commander OAuth facade and credential-pool gateway; recommendations below fit that small modular monolith.

## Evidence status

- **Documented:** statements below are from the linked official references.
- **Executed:** none. No endpoint behavior or price was tested live.
- **Experimental:** OpenTelemetry JS documents traces and metrics as stable and logs as development status; browser instrumentation is experimental.
- **Unsupported:** consumer browser/session credentials are not a general provider API credential. Use only a provider's documented CLI/client sign-in inside that client; do not export or replay its session tokens in Token2OAuth or Snooze.
- **Unknown:** the selected Nebius API overview and llama.cpp server documentation URLs returned 404. Their auth, catalog, stream, cost, usage, and capability details are left unresolved. Exact current per-token rates were not captured; use the official pricing pages before cost estimates.

### Subscription-auth CLI boundary

- [Codex authentication](https://developers.openai.com/codex/auth/) documents ChatGPT sign-in or API-key sign-in for local Codex clients; Codex cloud requires ChatGPT sign-in. This does not authorize using a copied Codex session as a general OpenAI API credential.
- [Claude Code IAM](https://docs.anthropic.com/en/docs/claude-code/iam) documents Claude Pro/Max, Teams/Enterprise, Console/API-key, and supported cloud-provider sign-in for Claude Code. Treat each as Claude Code auth, not a bearer key for arbitrary services.
- [Gemini CLI authentication](https://geminicli.com/docs/get-started/authentication/) offers Google-account, API-key, and Vertex routes with different quotas/terms. Its current page says Gemini CLI for unpaid-tier and Google One users was replaced by Antigravity CLI on 2026-06-18; re-check eligibility before recommending it.
- [Z.AI GLM Coding Plan](https://docs.z.ai/devpack/overview) names supported agent clients, including Claude Code, Codex, and OpenCode. Use its documented plan setup and quotas only; do not infer that a Z.AI subscription credential is portable to other clients.
- Ollama cloud documents API-key access; local Ollama is unauthenticated by default. No consumer subscription login should be turned into a shared service credential.

## Reuse candidates and fit

| Candidate | Evidence, license pointer, and fit |
|---|---|
| Official [MCP TypeScript SDK](https://github.com/modelcontextprotocol/typescript-sdk) | Official server/client SDK; repo records a recent licensing change to Apache-2.0, so check the exact package/version license before pinning. Useful if this product owns MCP protocol framing/transports; unnecessary for forwarding OAuth-protected HTTP. |
| SQLite durable jobs | SQLite [WAL behavior](https://sqlite.org/wal.html) supports concurrent readers with a writer, but SQLite still serializes writes and WAL has filesystem/process constraints. For one Node host, a small transactional jobs table with lease expiry, attempts, `next_run_at`, and idempotency key is lighter than a queue service. SQLite is public domain ([license](https://sqlite.org/copyright.html)); do not use this for multi-host distributed workers. |
| OpenTelemetry JS | [Official JS docs](https://opentelemetry.io/docs/languages/js/) cover metrics, traces and logs; [project license](https://github.com/open-telemetry/opentelemetry-js/blob/main/LICENSE) is Apache-2.0. Add API boundaries and redacted provider/model/latency/token attributes first; keep prompt and credential data out. Logs are still marked development status in the docs reviewed. |
| OpenCode provider/session patterns | [Provider docs](https://opencode.ai/docs/providers/) use AI SDK plus Models.dev for broad provider metadata and keep credentials/configuration separate. Borrow adapters, capability discovery and event/session shapes; do not add the whole application. Check its [MIT license](https://github.com/anomalyco/opencode/blob/dev/LICENSE). |
| Durable queue library | [BullMQ docs](https://docs.bullmq.io/) describe delayed/repeatable work, retries and crash recovery on Redis; [license](https://github.com/taskforcesh/bullmq/blob/master/LICENSE) is MIT. It adds Redis operations, so use it only if Redis already exists or distributed workers are a real requirement. Otherwise use SQLite leases on one host. |
| Langfuse and SigNoz | [Langfuse JS SDK](https://github.com/langfuse/langfuse-js) now builds tracing on OTel packages; its [license](https://github.com/langfuse/langfuse-js/blob/main/LICENSE) is MIT. It fits later if prompt/trace analytics are a product need, but adds an SDK and backend. [SigNoz’s self-host guide](https://signoz.io/docs/install/docker/) is an observability deployment, not a library; review its [server license](https://github.com/SigNoz/signoz/blob/main/LICENSE) and storage/collector requirements before adopting. Prefer OTLP export to an already-operated backend over bundling either platform. |

## Recommendation

Keep Token2OAuth as a modular monolith: add a narrow provider adapter interface around the existing Express proxy and Node `fetch` (`authenticate`, `listModels`, `complete`, `stream`, `normalizeUsage`, capability metadata). Preserve raw provider usage/cost fields alongside normalized values; treat model capability and price catalogs as dynamic provider data, not hard-coded promises. Start with documented API-key providers and keep subscription login inside supported first-party CLIs. The current package has no database, Redis, MCP SDK, telemetry, or job-queue dependency: add the official MCP SDK only if implementing MCP server transport, SQLite only for single-host durable refresh/retry work, and BullMQ only when Redis/distributed workers already justify it. Make OpenTelemetry optional at the application boundary; defer Langfuse/SigNoz until tracing needs and operations budget are explicit. Nebius and llama.cpp need verified official documentation before implementation.
