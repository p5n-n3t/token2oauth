## Findings and evidence

Snooze is currently a Python 3.11 service. `snooze.runtime.Runtime` is its composition root: it wires the legacy worker observer, the task control plane, provider adapters, scheduler, history API, and notification outbox. `snooze.web` serves a loopback-only HTTP API and static UI; `snooze.transport.LightSprint` is a credential-local MCP client pinned to the LightSprint MCP endpoint. Redirects are blocked in the current transport. [Runtime](https://github.com/p5n-n3t/snooze/blob/codex/snooze-command-centre/snooze/runtime.py) · [Web](https://github.com/p5n-n3t/snooze/blob/codex/snooze-command-centre/snooze/web.py) · [Transport](https://github.com/p5n-n3t/snooze/blob/codex/snooze-command-centre/snooze/transport.py)

The legacy observation store and control plane share `state.sqlite`. Versioned additive migrations create projects, tasks, attempts, artifacts, validations, events, policy revisions, and history facts. Migration makes a SQLite backup and sets the database file to mode `0600`; history facts are separate from scheduler events. The frontend is a separate Svelte/Vite package whose generated static assets are copied under `snooze/static`; setuptools includes those assets in the Python package. [Migrations](https://github.com/p5n-n3t/snooze/blob/codex/snooze-command-centre/snooze/migrations.py) · [Frontend scripts](https://github.com/p5n-n3t/snooze/blob/codex/snooze-command-centre/frontend/package.json) · [Packaging](https://github.com/p5n-n3t/snooze/blob/codex/snooze-command-centre/pyproject.toml)

## Token2OAuth reuse and safe migration

Token2OAuth is a Node 22+ TypeScript/Express application. Its composition root is `src/server.ts`; exported service interfaces are in `src/index.ts`; `src/store.ts` owns encrypted credentials and versioned JSON state with an atomic file-write lock. This differs materially from Snooze’s SQLite transaction and lease model. [Server](https://github.com/p5n-n3t/token2oauth/blob/main/src/server.ts) · [Store](https://github.com/p5n-n3t/token2oauth/blob/main/src/store.ts) · [Package](https://github.com/p5n-n3t/token2oauth/blob/main/package.json)

Recommended reuse is to keep `TaskRepository`, `Scheduler`, `Monitor`, provider adapters, validation, and `Outbox` as an isolated Python-owned subsystem initially. Integrate through a narrow typed service boundary rather than sharing the SQLite file with Token2OAuth’s JSON store or rewriting transactional lease logic into request handlers. If a Node rewrite is later justified, put orchestration behind a dedicated service module, wire it in `src/server.ts`, expose stable DTOs through `src/types.ts`, and leave OAuth credential selection/proxy behavior in `src/pool.ts` and `src/proxy.ts` unless a concrete requirement connects them.

For any ownership transfer, first run Snooze in observation/shadow mode, reconcile all remote sessions and saved artifacts, quiesce the current dispatcher, and only then switch executor ownership. Preserve an auditable snapshot/export and verify record/path scopes before enabling launches. Do not treat an expired timestamp, provider idle status, or launch receipt as proof that a lease can be released or work is complete.
