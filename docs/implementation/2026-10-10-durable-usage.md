# T2O-R45 durable usage receipts

Accepted operation results may now carry an optional `usage` object with exactly six fields: non-negative finite `reportedSessionCostUsd`, integer `promptCount`, non-negative finite `budgetUsed`, positive finite `maxBudget`, and bounded non-empty `fundingSource` / `sandboxTier` labels. Null usage is unavailable; malformed objects, booleans in numeric fields, non-finite values, extra keys, and invalid bounds are rejected. The accepted result and its supervisor receipt timestamp in epoch seconds are stored in the existing immutable `operations.result` JSON; no table was added. Idempotent result replays compare the receipt payload while preserving the first stored timestamp.

The task status DTO derives usage from the first accepted `chat_session` baseline and latest accepted `observe_session` receipt matching the current assignment, task, attempt, generation, account, and session. The durable supervisor acceptance timestamp orders receipts; legacy rows without it fall back to operation creation time. Absolute latest session cost and latest budget/funding/tier fields remain provisional reported values. Cost and prompt-count deltas are emitted independently only when both values are present, counters are nondecreasing, and reported models match. Mismatched session receipts are excluded. Retries, stale generations, malformed legacy data, and null/missing latest usage do not produce fabricated zeroes or deltas. The DTO labels the source `lightsprint-session-status`, marks the values provisional, and leaves `budgetUnit` unknown; it does not infer credit balance or invoice cost.

SQLite-backed tests exercise baseline/latest receipts, replay and restart durability, stale-generation exclusion, counter rollback, model/session mismatch, missing/null usage, and strict validation. `python3 -m unittest discover -v` passed all 219 tests.
