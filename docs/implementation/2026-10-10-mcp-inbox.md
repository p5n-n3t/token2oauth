# Project-scoped MCP job inbox

Implemented against integration head `c3f77b53d48e46c0abfab911831c9cb407126ba0` and the merged Python `supervisor/snooze/job_inbox.py` contract. `job_inbox` is read-scoped (`jobs:read`), accepts an opaque cursor string up to 128 characters and a page size of 1–100, and calls `GET /v1/inbox?projectId=…&after=…&limit=…`. `job_inbox_ack` is write-scoped (`jobs:write`), accepts only `repo:<positive id>` or `job:<positive id>` event IDs, and calls `POST /v1/inbox/{eventId}/ack` with `{ projectId }`.

Both runtime calls first require the configured OAuth client/project binding and use the runtime's existing `ownerPrincipalId: oauth-client:<clientId>` plus `clientId` bridge headers. Responses are projected to bounded inbox DTO fields; unknown bridge fields are dropped. The cursor remains opaque through validation and encoding. No global event endpoint, NULL owner, or fallback path was added.
